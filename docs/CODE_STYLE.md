# Code Style

Документ описывает единые правила оформления кода проекта.

Основная цель — сделать код читаемым, предсказуемым и единообразным для всех участников разработки.

---

# Общие принципы

При написании кода необходимо придерживаться следующих правил:

* код должен быть понятнее, чем короче;
* предпочтение отдаётся читаемости;
* одна сущность — одна ответственность;
* избегать дублирования кода;
* не использовать "магические" числа и строки;
* минимизировать связанность между модулями.

---

# Стиль именования

Проект использует **Microsoft C++ Naming Convention (PascalCase)**.

## Классы

Используется **PascalCase**.

```cpp
class NoteManager;
class HtmlExporter;
class TicketGenerator;
```

---

## Структуры

Используется **PascalCase**.

```cpp
struct NoteInfo;
struct TicketData;
```

---

## Перечисления

Используется `enum class`.

Название перечисления — **PascalCase**.

Элементы перечисления — **PascalCase**.

```cpp
enum class ExportFormat
{
    Html,
    Markdown,
    Pdf
};
```

---

## Пространства имён

Используется **PascalCase**.

```cpp
namespace Core
{
}

namespace Storage
{
}
```

---

## Методы и функции

Используется **PascalCase**.

Название должно начинаться с глагола.

```cpp
LoadNotes();

SaveDocument();

GenerateTickets();

ImportHtml();
```

---

## Переменные

Используется **camelCase**.

```cpp
currentNote

selectedTicket

outputPath

questionCount
```

---

## Поля класса

Используется **camelCase** с префиксом `m_`.

```cpp
m_notes

m_currentFile

m_ticketGenerator
```

---

## Параметры функций

Используется **camelCase**.

```cpp
LoadDocument(const QString& filePath);
```

---

## Константы

Используется **PascalCase** для `constexpr` и `const`.

```cpp
constexpr int MaxQuestionCount = 20;

const QString DefaultFileName = "notes.html";
```

# Форматирование

* один уровень отступа — 4 пробела;
* открывающая фигурная скобка располагается на новой строке;
* одна инструкция — одна строка;
* не использовать несколько операторов в одной строке.

Пример:

```cpp
if (document.IsValid())
{
    SaveDocument();
}
```

---

# Размер функций

Рекомендуемый размер функции — до 40 строк.

Если функция начинает выполнять несколько различных действий, её следует разделить.

---

# Комментарии

Комментарии должны объяснять **почему**, а не **что** делает код.

Плохой пример:

```cpp
// Увеличиваем счетчик
counter++;
```

Хороший пример:

```cpp
// Повторная обработка документа невозможна,
// поэтому увеличиваем номер версии после сохранения.
counter++;
```

Если код достаточно понятен без комментариев — комментарий не нужен.

---

# Использование auto

`auto` рекомендуется использовать только в случаях, когда тип очевиден.

Допустимо:

```cpp
auto iterator = notes.begin();

auto widget = std::make_unique<EditorWidget>();
```

Не рекомендуется:

```cpp
auto value = GetSomethingComplicated();
```

Если тип не очевиден, его следует указать явно.

---

# Указатели

Предпочтительно использовать:

* `std::unique_ptr`
* `std::shared_ptr`

Использование "сырых" указателей допускается только если объектом не владеют.

Вместо `NULL` использовать `nullptr`.

# include

Порядок подключения файлов:

1. собственный заголовочный файл;
2. стандартная библиотека C++;
3. Qt;
4. файлы проекта.

---

# Заголовочные файлы

Каждый заголовочный файл должен содержать только объявления.

Реализация располагается в `.cpp`.

---

# Принципы написания кода

При разработке рекомендуется соблюдать:

* SRP (Single Responsibility Principle);
* DRY (Don't Repeat Yourself);
* KISS (Keep It Simple, Stupid);
* YAGNI (You Aren't Gonna Need It).

Любое отклонение от данных правил должно быть обосновано.
