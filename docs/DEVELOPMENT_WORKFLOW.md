# Development Workflow

Процесс разработки построен на основе GitHub Projects и Kanban.

Каждая задача проходит одинаковый жизненный цикл.

```
Backlog
    ↓
Ready
    ↓
In Progress
    ↓
Code Review
    ↓
Testing
    ↓
Done
```

## Backlog

Все идеи, предложения и будущие задачи.

Задачи находятся в ожидании и ещё не готовы к разработке.

---

## Ready

Задача полностью подготовлена.

Определены:

* цель;
* требования;
* критерии готовности.

После этого разработчик может взять её в работу.

---

## In Progress

Функциональность находится в активной разработке.

Разработчик реализует задачу в отдельной рабочей ветке.

---

## Code Review

Разработка завершена.

Создан Pull Request.

Проводится проверка:

* качества кода;
* соответствия архитектуре;
* соблюдения Code Style;
* полноты реализации.

При необходимости задача возвращается в стадию **In Progress**.

---

## Testing

После успешного Code Review выполняется проверка работоспособности изменений.

Проверяется:

* корректность работы новой функциональности;
* отсутствие регрессий;
* соответствие требованиям задачи.

При обнаружении проблем задача возвращается в **In Progress**.

---

## Done

Задача считается завершённой после успешного прохождения всех предыдущих этапов.

Изменения объединены в ветку `develop`, а рабочая ветка удалена.
