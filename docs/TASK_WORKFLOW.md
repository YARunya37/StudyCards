# Task Workflow

Документ описывает требования к постановке задач, их выполнению и критериям завершения.

Цель документа — сделать процесс разработки предсказуемым, а требования к задачам понятными для всех участников проекта.

---

# Жизненный цикл задачи

Каждая задача проходит следующие этапы:

1. Постановка задачи.
2. Подготовка требований.
3. Реализация.
4. Code Review.
5. Тестирование.
6. Завершение.

Движение задачи между этапами осуществляется через GitHub Projects в соответствии с документом **Development Workflow**.

---

# Структура задачи

Каждая задача должна содержать достаточную информацию для её самостоятельного выполнения.

## Название

Название должно кратко описывать функциональность.

Хорошие примеры:

```text
Добавить экспорт конспектов в PDF

Реализовать генерацию экзаменационных билетов

Исправить сохранение HTML-документов
```

---

## Цель

Краткое описание того, какую проблему решает задача.

Пример:

```text
Добавить возможность экспортировать конспекты в PDF для удобной печати и обмена материалами.
```

---

## Описание

Подробное описание реализации.

Необходимо указать:

* что необходимо реализовать;
* ограничения;
* особенности поведения;
* требования к пользовательскому интерфейсу (при необходимости).

---

## Критерии готовности

Каждая задача должна содержать список критериев, по которым можно определить, что она выполнена.

Пример:

```text
- экспорт работает для всех поддерживаемых документов;
- сохраняется форматирование;
- ошибки корректно обрабатываются;
- функциональность протестирована.
```

---

## Дополнительная информация

При необходимости могут быть указаны:

* ссылки на связанные задачи;
* макеты интерфейса;
* архитектурные ограничения;
* технические заметки.

---

# Декомпозиция

Задачи должны иметь разумный размер.

Если реализация занимает значительное время или затрагивает несколько независимых компонентов, её следует разделить на несколько отдельных задач.

Предпочтительно создавать небольшие задачи, которые можно выполнить и проверить независимо друг от друга.

---

# Выполнение задачи

Перед началом работы необходимо:

* ознакомиться с описанием задачи;
* убедиться, что требования понятны;
* при необходимости уточнить детали реализации.

Во время выполнения задачи рекомендуется:

* придерживаться существующей архитектуры;
* соблюдать Code Style;
* выполнять небольшие логически завершённые коммиты;
* регулярно синхронизировать рабочую ветку с `develop`.

---

# Завершение задачи

Перед созданием Pull Request разработчик должен убедиться, что:

* функциональность реализована полностью;
* требования задачи выполнены;
* код соответствует Code Style;
* отсутствуют известные ошибки;
* проект успешно собирается;
* очень желательно протстировать функционал компонентов, которые были затронуты
* при необходимости обновлена документация.

---

# Definition of Done

Задача считается завершённой только при выполнении всех следующих условий:

* реализована вся требуемая функциональность;
* выполнены критерии готовности;
* создан Pull Request;
* успешно пройден Code Review;
* устранены замечания ревью;
* успешно выполнено тестирование;
* изменения объединены в ветку `develop`;
* рабочая ветка удалена.

Только после выполнения всех перечисленных условий задача переводится в статус **Done**.

---

# Изменение требований

Если в процессе разработки изменяются требования или появляются новые идеи, они не должны добавляться в текущую задачу без обсуждения.

Если изменение выходит за рамки первоначальной цели, рекомендуется создать новую задачу в Backlog и выполнить её отдельно.
